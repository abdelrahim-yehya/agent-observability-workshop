Method

Choosing the tools

Most tools are documented in repositories, vendor pages and blogs, so we searched GitHub and Google with fixed queries on 22 Oct 2026 and screened the results by hand against written inclusion and exclusion rules. The OpenTelemetry conventions for generative AI were added by hand, since a specification has no product page for such queries to rank.

Collecting the metrics

For each tool we read the official documentation and recorded every built-in metric: one the tool itself ships, as opposed to a metric the user writes, a community contribution or one reached through an integration. We kept the metrics that describe how an agent run executes or how good its output is. Each of the 298 rows stores the page, a verbatim quote, a saved copy of the page and the date, and a script checks that every quote appears word for word in the saved copy.

Merging them

Two metrics from different tools become one unique metric when they measure the same thing about the same object, whatever the tools call them. The mapping (377 pairs) is made by hand. The definitions on this site are ours, not quotations.

Reading the catalogue with care

  • Tools that share a unique metric may compute it differently, and can disagree on the same run.
  • An empty cell means we found nothing in the pages we read. It does not prove the tool lacks the metric.
  • Documentation changes. Every quote carries the date its page was read.
  • Text-match and format checks, retrieval scores, audio, voice and image metrics and task-specific metrics are out of scope.
  • Closed-source tools that the search results did not name are absent.
