# Agent Metrics Catalogue: the website

The companion website of the paper "A Catalogue of Observability and Evaluation Metrics for AI Agents". It presents the taxonomy, the 46 unique metrics with their definitions, and the tools that ship each one, with the documentation evidence behind every claim.

It is a static site: plain HTML, one stylesheet and one script. There is nothing to install and no build step to view it.

## Run it

From the repository root, either open it straight from disk:

```bash
open site/index.html          # macOS; on Linux use xdg-open, on Windows start
```

or serve it locally:

```bash
python3 -m http.server -d site 8000
```

and go to <http://localhost:8000>. Both ways show the same site; all links are relative. The only thing loaded from the internet is the font, and the pages fall back to system fonts without a connection.

## What it shows

| Page | Content |
| --- | --- |
| `index.html` | Summary numbers and the taxonomy: the two types (observability, evaluation) and 13 categories, with every metric and how many of the 13 tools ship it |
| `metrics.html` | The catalogue: the 46 unique metrics with definitions, searchable and filterable by type, category and tool |
| `metrics/<metric>.html` | One page per metric: our definition, the tools that ship it and, for each tool, its own name for the metric, the sentence of its documentation we rely on, the link to the page, the date it was read and the saved copy |
| `tools/<tool>.html` | One page per tool or set of telemetry conventions: how it was selected, stars and downloads, the metrics it ships under its own names, and what it offers for the others |
| `coverage.html` | The full table of every metric against every tool, with the status of each cell (built-in, through an integration, can be built, nothing found) |
| `tools.html` | The 13 tools and the three sets of telemetry conventions, grouped as they were selected |
| `method.html` | How the tools were chosen, how the metrics were collected and merged, and what to keep in mind when reading the catalogue |

The catalogue filters can be set from the address, for example `metrics.html?tool=Langfuse`, `metrics.html?type=Evaluation` or `metrics.html?q=tokens`.

## Rebuild it

Every page is generated by `src/build_site.py` from the data in `results/` and `data/inputs/`. Do not edit the HTML by hand: it is overwritten on the next build. After the data changes, run:

```bash
python3 src/build_taxonomy.py
python3 src/build_matrix.py
python3 src/build_site.py
```

Counts, names, definitions, quotes and links come from the data. The short prose (introduction, category descriptions, method summary) is written in `src/build_site.py` and follows the paper, so update it there when the paper changes.

## Publish it

The site is not hosted yet. Because it is static and uses relative links, the `site/` folder can be published as it is on any static host (GitHub Pages, Netlify, Vercel or a university web server).
