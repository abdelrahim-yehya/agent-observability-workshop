# Release Notes

> Recent updates and enhancements to Galileo

**2026-10-27**

Decision model metrics

## Create decision model metrics

Create decision model metrics to classify and score large volumes of text faster and at a much lower cost than LLM-as-a-judge metrics. This release includes support for TypeSafe Jev decision models. [Learn more](https://docs.galileo.ai/concepts/metrics/custom-metrics/custom-decision-model-metrics.md)

**2026-10-13**

Control metric access by project and role

## Control metric access by project and role

Choose whether a metric is global and available in every project, or project-scoped and available in selected projects. A user's project role determines their access to project-scoped metrics. [Learn more](https://docs.galileo.ai/concepts/access-control.md#metric-access)

**2026-08-07**

Galileo is now Splunk Agent Observability

## Galileo is now Splunk Agent Observability

As of August 7, 2026, Galileo is now Splunk Agent Observability.

The documentation on this website applies to customers who onboarded prior to August 7, 2026. If you onboarded after this date, use the documentation on [agent-observability-docs.splunk.com](https://agent-observability-docs.splunk.com).

**2026-06-23**

## Key new features and improvements

### Evaluate multi-turn conversations in experiments

The Galileo [Python SDK](https://docs.galileo.ai/sdk-api/python/sdk-reference.md) now supports evaluating multi-turn conversations in [experiments](https://docs.galileo.ai/sdk-api/experiments/experiments.md). With this feature, you can use Galileo session metrics to test how multi-turn datasets perform on your agents before deploying changes to production.

![Multi-turn conversations in experiments screenshot](https://mintcdn.com/v2galileo/AVWLNcoYB2AlXTO9/images/release-notes/2026-06-23/multi-turn-conversations-experiments.png?fit=max\&auto=format\&n=AVWLNcoYB2AlXTO9\&q=85\&s=c7eb42ff2203c455a999f36f83578933)

Out-of-the-box session metrics include [Action Completion](https://docs.galileo.ai/concepts/metrics/agentic/action-completion.md), [Agent Efficiency](https://docs.galileo.ai/concepts/metrics/agentic/agent-efficiency.md), [Agent Flow](https://docs.galileo.ai/concepts/metrics/agentic/agent-flow.md), [Conversation Quality](https://docs.galileo.ai/concepts/metrics/agentic/conversation-quality.md), [Interruption Detection](https://docs.galileo.ai/concepts/metrics/multimodal-quality/interruption-detection.md), and [User Intent Change](https://docs.galileo.ai/concepts/metrics/agentic/intent-change.md). You can also [create your own custom metric](https://docs.galileo.ai/concepts/metrics/custom-metrics/custom-metrics-ui-llm.md) to evaluate sessions.

Usage steps:

1. Define multi-turn datasets and experiments using the Python SDK.
2. Configure out-of-the-box or custom session metrics on these experiments.
3. View the sessions and metrics in the **Experiments** UI in a new **Sessions** tab.

[Learn more](https://github.com/rungalileo/sdk-examples/tree/main/python/experiments/multi-turn)

### Test metrics using datasets

Validate a custom metric against a labeled dataset and get a macro F1 score or RMSE for how well it matches metric ground truth. Trust metrics before deploying, catch drift, and confirm Autotune improvements. [Learn more](https://docs.galileo.ai/concepts/metrics/custom-metrics/test-metrics.md)

**2026-03-27**

Autotune, Editable trends view, Metric roll-up features, Dataset and Experiments UI improvements

## Key new features and improvements

### Autotune

Galileo now supports Autotune, an enhancement to Continuous Learning via Human Feedback (CLHF) to improve performance of LLM-as-a-judge metrics. Instead of manually tuning prompts, anyone on your team can provide feedback in natural language to:

[Autotune: Improve LLM-as-a-Judge Metrics with Expert Feedback](https://www.youtube.com/embed/fwlhZ6-W-I4)

* correct metric outputs and enter expected values
* let Galileo adapt the metric prompt and show exactly what changed
* test prompt changes before publishing and optionally recompute historical results
* apply improvements to future runs across out-of-the-box and custom LLM-as-a-judge metrics

To autotune a metric, hover over any LLM-as-a-judge metric and click **Add feedback**. [Learn more](https://docs.galileo.ai/concepts/metrics/autotune-llm-as-a-judge-metrics.md).

### Editable trends view

Galileo now supports a fully editable trends view, giving every team control over exactly what they monitor — all from the same logstream.

[Editable Trends View](https://www.loom.com/embed/bcdd51decc874adfb5e69464d4df7473)

* drag, reorder, duplicate, and delete widgets and sections in edit mode
* customize each widget's aggregation, properties and visualization type
* customize and persist filters, time range, and interval settings

To get started, go to **Logstreams → Trends** and click **Edit layout**.

### Metric roll-up features

Span and Trace level metrics are now rolled up to the Session level for any metrics computed in the logstreams. This helps you identify problematic sessions that might need more investigation without digging deeper into Trace and Span levels.

You can now customize the logic used to roll-up metric computations. For example, you can customize how Span-level metrics are shown at Trace and Session levels.

![Metric roll-up logic modal (a new metric)](https://mintcdn.com/v2galileo/McbURK5J885gOrC6/images/release-notes/2026-03-27/metric-rollup-new-metric.png?fit=max\&auto=format\&n=McbURK5J885gOrC6\&q=85\&s=a53d00d027eae0bdb051e868f525a0ab)

This new roll-up option appears on metrics with "Output type" of "Count" or "Percentage". A new "Roll-up logic" menu item appears on existing metrics with count and percentage output types.

![Metric roll-up logic menu item (existing metric)](https://mintcdn.com/v2galileo/McbURK5J885gOrC6/images/release-notes/2026-03-27/metric-rollup-existing-metric.png?fit=max\&auto=format\&n=McbURK5J885gOrC6\&q=85\&s=a544b43cb5a5ef470af9dba353b2af03)

#### Export via the Python SDK

The Python SDK [`export_records` function](https://docs.galileo.ai/sdk-api/python/reference/export) supports exporting from code. Example code snippet:

```python theme={null}
from galileo import GalileoLogger
from galileo.export import export_records
from galileo.projects import get_project
from galileo.resources.models import LLMExportFormat
from galileo.resources.models.root_type import RootType


project = get_project(name=PROJECT_NAME)
logger = GalileoLogger(project=PROJECT_NAME,
                      log_stream=LOG_STREAM_NAME)


records = export_records(project_id=project.id,
                        root_type=RootType.SESSION, # or RootType.TRACE or RootType.SPAN
                        export_format=LLMExportFormat.JSONL) # or LLMExportFormat.CSV

print(list(records))
```

### Agentic metrics for workflow evaluations

Galileo has four new metrics specifically designed for agent workflows. Use these metrics to track efficiency, quality, and intent across multi-step agent processes.

These metrics include:

* **Agent Flow** - Ensures the agent followed the ideal execution path.
* **Agent Efficiency** - Rewards concise, goal-oriented behavior while avoiding redundant steps or unnecessary tool calls.
* **Conversation Quality** - Session-level metric for evaluating overall conversation quality. Uses multi-trace inputs/outputs and does not require thinking logs or tool logs.
* **Intent Change** - Detects user intent shifts throughout a conversation, helping identify changes in user goals.

**2025-05-02**

Metrics on experiments UI, public APIs, and more

## Key new features

### Metrics on experiments UI

You can now compute additional metrics for logged experiments directly within the experiments UI. Until now, users didn't have a way to compute more metrics for logged experiments from the UI or SDK.

![Metrics on experiments UI](https://mintcdn.com/v2galileo/FQjmOk8BWj4bvBe1/images/AddingMetricstoExperimentsinUI-ezgif.com-optimize.gif?s=1e68c0883aa5167bced24d456a4e53ac)

### Public APIs

Released [public APIs](https://docs.galileo.ai/sdk-api/overview.md) to allow developers to manage Log streams, experiments, and trace data programmatically. While these can already be managed through the TypeScript and Python SDK, public APIs allow users to programmatically interact with these components in any language. Sample use cases include logging data from a production AI app, running experiments, and retrieving evaluation result

### Aggregate metrics and ranking criteria for experiments

Added to All Experiments page. Aggregate metrics compile the metric values from individual traces in an experiment to show a combined value for each metric on the all experiments page. This enables you to quickly assess the performance of the underlying traces in an experiment. Ranking criteria allow you to determine which experiments were most successful by specifying a weighted average of the underlying metrics for each experiment.

![Ranking Criteria Interface](https://mintcdn.com/v2galileo/FQjmOk8BWj4bvBe1/images/Added-aggregate-metrics.png?fit=max\&auto=format\&n=FQjmOk8BWj4bvBe1\&q=85\&s=114425930befb3631f1a42a649e5724d)

### Reference output and metadata availability

The reference output and metadata from the datasets are now available in the corresponding experiment traces so it can easily referenced.

![Reference Output Interface](https://mintcdn.com/v2galileo/FQjmOk8BWj4bvBe1/images/Reference-output-and-metadata-from-datasets.png?fit=max\&auto=format\&n=FQjmOk8BWj4bvBe1\&q=85\&s=9e76b25ed398de383610898d59beb5ed)

When uploading datasets from a CSV or JSON file, the contents of a column are automatically flattened to text instead of being stored as JSON when there's only one file column mapped to an input, output or dataset column.
